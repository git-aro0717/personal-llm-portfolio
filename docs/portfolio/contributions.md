# AI支援と人間の担当範囲

このプロジェクトはAI支援を利用して開発した。自力実装だけの成果として表現しない。
以下は開発指示・既存資料・実行記録から確認できる範囲であり、作業時間や寄与率は算出していない。

| 区分 | 記録から確認できる内容 |
|---|---|
| 人間の目的・要件 | 個人用LLM、層の分離、Mock維持、履歴・文書検索・削除安全性、費用と操作範囲の指定 |
| 人間の構成採用・判断 | localhost中継とAWS_IAM、Secrets Manager利用、SQLite採用、v1.0/CSVの分離、課金・削除・変更セットの承認 |
| 人間の環境作業 | PowerShellへのキー設定、AWS管理画面のSecret/IAM設定、Docker再起動・SAMビルドの実行と結果共有 |
| 人間の確認 | Web UIでの応答・出典の確認、中継再起動、E2Eの段階的承認・結果確認 |
| AIによる支援 | コード・テスト・資料の作成、設計候補・リスク・権限案の提示、ログ・台帳・履歴調査、許可範囲内のローカル検証と操作支援 |
| 人間とAIの共同工程 | 障害仮説の比較、削除受理と反映確認の区別、失敗後の停止・再開条件、テスト計画と結果の解釈 |

各行を誰が書いたか、すべての判断を人間が独立に導いたかはGitから判定できない。
Git作者名だけを、人間が全コードを手書きした証拠として扱わない。
AIの説明だけを成果証明にせず、ソース・自動テスト・限定実API検証を区別して記録した。

面接では、構成を採用した理由、責任境界、異常系、削除状態遷移、未保証事項を説明対象にする。
LLMの学習、独自検索エンジン、高負荷運用、商用の複数ユーザー基盤の開発経験としては主張しない。
